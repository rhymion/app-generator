# Security Policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately through GitHub's private
vulnerability reporting: open the repository's **Security** tab and choose
**Report a vulnerability**. Please do not open a public issue, pull request or
discussion for a suspected vulnerability.

A useful report describes the affected component, the version or commit, the
steps to reproduce, and the impact you expect.

## Scope

In scope:

- this generator, and
- the code the generator produces.

Out of scope:

- code that a consumer application adds by hand,
- environments that someone has deployed.

## Supported versions

Only the latest major version (currently 6.x) receives security fixes.
Earlier versions are not patched.

## What to expect

- We acknowledge a report within 5 business days.
- We give a first assessment within 10 business days.
- We fix the issue in a private security advisory, release the fixed version,
  and then publish the advisory and request a CVE identifier.
- We credit the reporter in the advisory unless asked not to.

## Safe harbor

If you make a good-faith effort to follow this policy, avoid harming other
people's data and systems, and report privately, we will not pursue action
against your research.
