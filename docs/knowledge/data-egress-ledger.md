# Data-egress ledger

One row per (protected data class, outbound route): every way the data of a class can leave a generated application
(Issue #1240). The classes are those of [data-classification.md](data-classification.md); the destinations of the
running application are in [outbound-communications.md](outbound-communications.md) and their security contracts in
[external-service-security-contracts.md](external-service-security-contracts.md).

Read it by class: to know where personal data can go, filter the rows for "Personal data".

## Adding an outbound route

A change that adds a route by which data leaves the application adds its row here, in the same change:

- **An API route** (generated or hand-written): add an entry for the route file to
  `code_generator/egress_ledger_classes.yaml` (`classes` it releases, and what leaves in `data`; `classes: []` with
  the reason for a route that releases no protected data), then run `python code_generator/egress_ledger.py --write`.
  A route with no entry, an entry for a route that is gone, or a stale generated block fails
  `code_generator/tests/test_egress_ledger.py` (part of `npm run test:pytest`). A new GET operation of the OpenAPI
  document is business data unless a prefix in `openapi_prefixes` says otherwise; add a prefix for an entity that
  holds personal data.
- **Anything else** (a new log sink, storage backend, mail, a third-party service): add a row to the table under
  "Other routes" by hand, and the destination to `outbound-communications.md` (which
  `test_outbound_dependency_classification.py` enforces for a new dependency or fixed host).

The pull-request template asks for this row.

## Other routes

Written by hand. A row names what leaves, not every field.

| Class | Route | What leaves | Control |
|-------|-------|-------------|---------|
| Secret | Application log (process output, platform log drain) | Nothing by design | `lib/logger.ts` redacts credential-named keys, bearer tokens, JWTs ([logging.md](logging.md)) |
| Personal data | Application log | User ids; email addresses only if a redaction rule misses them | Email addresses redacted by value pattern ([logging.md](logging.md)) |
| Operational record | Application log | Error classes, security events, swallowed failures ([logging-inventory.md](logging-inventory.md)) | JSON lines, redacted |
| Operational record | Audit-log write-once copies (GCS or S3) | Period digests and archived `audit_log` partitions | Write-once storage with retention ([audit-log-append-only.md](audit-log-append-only.md)) |
| Personal data | Audit-log write-once copies | Actor user ids in archived rows | Same; emails and free text are kept out of `audit_log` metadata |
| Business data | Attachment storage (GCS, Vercel Blob or local disk) | Uploaded file content | Private bucket or store, opaque keys ([attachment-storage.md](attachment-storage.md)) |
| Personal data | Attachment storage | File content that may hold personal data; original file names are encrypted before storage | AES-256-GCM file names ([data-classification.md](data-classification.md)) |
| Secret | Database (PostgreSQL) | Password hashes, API key hashes, encrypted MFA secrets, session rows | Hashing and encryption at rest ([data-classification.md](data-classification.md)); TLS per `DATABASE_URL` |
| Personal data | Database | User columns marked `x-pii` | TLS per `DATABASE_URL` |
| Business data | Database | Entity rows | TLS per `DATABASE_URL` |
| Personal data | Redis (rate limiting) | Rate-limit counters keyed by user id, client IP or a hash of an email address | Keys only, no payloads; TLS per `REDIS_URL` |
| Personal data | SMTP server (mail) | Recipient email address and name in verification, password-reset and email-change mail | Only with `x-generator.email-verification` ([authentication.md](authentication.md)) |
| Secret | SMTP server (mail) | Single-use links (verification, password reset, email change) | Single-use, short-lived tokens; stored hashed |
| Secret | Have I Been Pwned | The first 5 hex characters of the SHA-1 of a new password | Only with `PASSWORD_BREACH_CHECK=hibp`; k-anonymity range query |
| Secret | Google token exchange | The Vercel OIDC token, exchanged for short-lived Google credentials | Only with `AUDIT_LOG_GCS_AUTH=vercel-oidc` |
| Personal data | Google sign-in | The OAuth authorization code and PKCE verifier; Google returns the user's profile | Only when Google sign-in is configured |
| Business data | Stripe | Price id, quantity and the `payable` id (as `client_reference_id` and metadata) | Only for a schema with `x-payment: true` ([stripe-payment-integration.md](stripe-payment-integration.md)) |
| Secret | Mobile device | Access and refresh tokens, kept in the platform keychain (`expo-secure-store`) | Short-lived access token; refresh token rotated on use ([mobile-app.md](mobile-app.md)) |

OpenAPI document, and every other API route with its entry in `code_generator/egress_ledger_classes.yaml`. Write
operations of the OpenAPI document answer with ids and status only and are not listed. Every response is subject to
the caller's permissions and organization; a consumer app's own schema adds rows for its entities (run the script in
that project).
