## 2. Data we collect

- **Account data**: name, email address, and a securely hashed password (or,
  if your administrator enables it, a linked Google account instead of a
  password).
- **Multi-factor authentication (MFA) data**, only if you enable it on your
  own account: a TOTP secret and one-time recovery codes, stored hashed.
- **Organization data**: which organization (tenant) and role(s) you belong
  to. Data is isolated per organization — the Service does not let one
  organization read another's data.
- **Content you create**: records you create, edit, comment on, or submit
  for approval within the Service.
- **File attachments** you upload, plus metadata (file name, type, upload
  time). Depending on how this deployment is configured, files are stored
  either on the application server's file system or with a cloud storage
  provider (for example Vercel Blob or Google Cloud Storage); some
  deployments encrypt the stored file name. `[PLACEHOLDER: confirm which
  storage backend and encryption settings this deployment actually uses]`.
- **Audit log**: security- and accountability-relevant actions (who did
  what, to which record, and when) are recorded internally and are visible
  to users with audit log access within your organization.
- **In-app notifications**: notifications generated by activity in the
  Service (e.g. approval requests) are stored so they can be shown to you
  across sessions.
- **Session data**: an authentication session cookie is set when you sign
  in, so the Service can recognize you on later requests. This cookie is
  used only for authentication, not for cross-site tracking.
